# Headless Form Handler

A JSON API for defining forms, accepting submissions from any website, and alerting people when entries arrive. There is no web interface: forms are rendered elsewhere and post to the API.

Product requirements live in [`docs/prds`](docs/prds/README.md). Once the app is running, the API reference is served at `/docs/api` (the bare domain redirects there).

## Requirements

- PHP 8.3 or newer (8.4 recommended), with the `pdo_sqlite` extension for the default database
- [Composer](https://getcomposer.org/)

## Installation

```bash
git clone git@github.com:adriangonzales/form-handler-headless-laravel.git form-handler
cd form-handler
composer run setup
```

The Composer setup script:

 - Installs composer dependencies & creates autoload
 - Copies `.env.example` to `.env` if it doesn't already exist
 - Generates Laravel secret key
 - Generates JWT Secret key
 - Migrates database files

These commands can also be accomplished like this:

```bash
composer install
php -r "file_exists('.env') || copy('.env.example', '.env');"
php artisan key:generate
php artisan jwt:secret --no-interaction
php artisan migrate --force
```

`key:generate` sets `APP_KEY`, used for encryption. `jwt:secret` sets `JWT_SECRET`, used to sign API tokens. Changing `JWT_SECRET` later signs every user out.

API tokens last `JWT_TTL` minutes (default 60). They can be refreshed until `JWT_REFRESH_TTL` minutes (default 10080, 7 days) after login, after which the user must log in again.

The default `.env` uses SQLite (`database/database.sqlite`). To use MySQL or PostgreSQL instead, set `DB_CONNECTION` and the `DB_*` values in `.env` before running migrations.

### Create an account

There is no sign-up endpoint. Create account holders from the command line:

```bash
php artisan user:create --name="Ada Lovelace" --email=ada@example.com
```

The password is prompted for, so it stays out of your shell history.

## Running the app

Start the HTTP server:

```bash
php artisan serve
```

The API is then available at `http://127.0.0.1:8000/api/v1`.

## API Documentation

The API Documentation is then available at `http://127.0.0.1:8000/docs/api/`.

## Example Form

A basic no-dependency example form is provided at [docs/example-form.html](docs/example-form.html). The form field ULIDs will need to be updated with the ones generated by your system.

## Queue worker

Alert emails, user-agent parsing and entry exports run on the queue (`QUEUE_CONNECTION=sync` by default). Setting this to Database or Redis will increase response time, but nothing is sent or generated until a worker is running. In a second terminal:

```bash
php artisan queue:work
```

Restart the worker after deploying code changes (`php artisan queue:restart`), since a running worker keeps the old code in memory. In production, keep it running with a process monitor such as Supervisor.

### Scheduler

Expired entry exports and deny-listed tokens are cleaned up by an hourly `model:prune`. Locally, run the scheduler with:

```bash
php artisan schedule:work
```

In production, add the standard Laravel cron entry instead:

```cron
* * * * * cd /path/to/form-handler && php artisan schedule:run >> /dev/null 2>&1
```

## Email

`MAIL_MAILER=log` by default, so alert and password reset emails are written to `storage/logs/laravel.log`. To send through Postmark, set `MAIL_MAILER=postmark` and `POSTMARK_API_KEY`; see `.env.example` for the bounce webhook settings. `PASSWORD_RESET_URL` is the page in your client app that reset emails link to.

### Postmark Bounce Webhook
The bounce webhook URL is https://USERNAME:PASSWORD@your-host/api/v1/webhooks/postmark/bounces

POSTMARK_WEBHOOK_USERNAME=
POSTMARK_WEBHOOK_PASSWORD=
